# 角色权限树实施计划

> 设计依据：`docs/superpowers/specs/2026-07-29-role-permission-tree-design.md`

## 1. 盘点与约束确认

- 确认 `src/views/admin/index.vue` 中角色编辑、菜单编辑、权限展示和保存逻辑的调用链。
- 确认后端继续接收扁平的 `module:action` 权限，系统管理角色限制和乐观锁不变。

## 2. 先建立可验证的权限树转换逻辑

- 新建独立的前端权限树工具，定义模块、操作节点、树节点和“选中权限集合”的转换。
- 为该工具添加可运行的单元测试：模块选中补齐 VIEW、回填选中、父级半选、非系统角色
  不包含 `systemAdmin:*`。
- 仅在测试覆盖转换规则后接入界面。

## 3. 改造角色编辑弹窗

- 替换平铺复选框为 Element Plus 树形复选框，并加入展开/折叠、全选/全不选、父子联动。
- 将权限树的选中节点转换为 `roleForm.permissions`；保存时保留原有版本号和请求参数。
- 利用现有 `openRoleEdit` 的返回权限完成回显，并继续让后端校验系统管理权限。

## 4. 合并菜单授权入口

- 删除“菜单权限”页签、菜单弹窗及其独立保存逻辑。
- 角色列表的已授权操作展示改为按模块归类，避免长串英文编码或重复标签。

## 5. 验证

- 运行新建的权限树单元测试。
- 运行 `npm run build`。
- 以 R00/R06 和普通角色分别手工验证：回显、全选、父子联动、保存、重新打开和菜单可见性。
- 确认普通角色无法通过界面写入系统管理权限，并保留后端最终限制。

## 6. 已授权操作摘要

- 为角色列表新增按模块归并的展示转换，过滤未知权限并保持操作固定排序。
- 将平铺标签替换为模块摘要标签；无授权仍显示“暂无授权”。
- 添加单元测试覆盖同一模块多操作归并、操作排序和空权限。
- 运行完整前端单元测试与 `npm run build`。

## 7. 权限详情抽屉

- 增加权限详情的只读抽屉状态与当前角色引用。
- 角色列表改为授权模块数摘要，并增加打开抽屉的操作入口。
- 在抽屉中复用模块归并转换，以模块卡片和中文操作标签展示权限与数据范围。
- 添加单元测试覆盖可识别权限模块计数；运行完整测试和构建。

## 8. 模块分块编辑窗口

- 为权限转换工具补充模块选择状态、禁用操作和保存前有效性测试。
- 将角色编辑对话框替换为模块分块复选框，并保留数据范围配置。
- 添加必填原因输入；前端在无模块或空原因时阻止请求。
- 将原因传给既有更新接口，继续使用版本号乐观锁与后端系统管理限制。
- 运行完整单元测试和生产构建。
