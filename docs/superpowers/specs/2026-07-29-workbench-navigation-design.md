# 工作台紧凑导航设计

## 目标

将工作台从纵向的大卡片布局改为首屏可见的紧凑导航页面。保留现有角色权限过滤、模块路由和快捷操作，不改变业务数据与入口权限。

## 信息结构

1. 顶部保留问候、当前分公司、角色和登录时间，但缩短垂直高度。
2. 功能导航作为页面主区域：按现有 `NAV_GROUPS` 分组展示。
3. 每个分组使用紧凑容器，内部以两列小入口展示模块；仅显示图标和模块名称，不再重复长描述。
4. 搜索框放在“功能导航”标题右侧，用于快速筛选模块，不单独占据一行或一个区块。
5. 常用操作位于导航下方，保留为低高度的横向按钮，避免与功能导航争夺首屏空间。
6. Mock 演示提示移到页面底部，以可关闭的紧凑提示呈现。

## 视觉规范

- 页面背景：`#f5f7fa`；内容区域最大宽度约 1180px。
- 主导航容器：白色表面、`12px` 圆角、细边框 `#ebeef5`。
- 分组标题：浅灰底色和业务名称，用颜色弱化的左侧强调线区分层级。
- 模块入口：两列网格、小图标方块（约 28px）加单行名称；悬停时只使用浅蓝底色和边框变化，不做大幅位移。
- 搜索框：宽度约 260px，与导航标题同一行；窄屏下改为整行。
- 常用操作：紧凑按钮而不是大卡片。

## 响应式规则

- 桌面端：每行最多三个业务分组，每组内部两列入口。
- 中等屏幕：分组为两列。
- 手机端：分组为单列；每组内部仍保持两列，搜索框换行到标题下方。

## 行为与边界

- 模块可见性继续以 `auth.hasModule` 与现有角色权限为准。
- 点击入口继续使用当前路由路径，不修改路由表或后端接口。
- 搜索继续按模块名称和已有描述匹配；无结果时保持现有空状态。
- 快捷操作只显示当前角色可访问的模块。

## 验收标准

- 具备常规模块权限的账号在 1366px 宽度下，无需滚动即可看到问候区、搜索、全部导航分组和常用操作。
- 搜索位于功能导航区域内，且可筛选当前有权限的模块。
- 不同角色只看到其有权限的导航入口。
- 桌面与手机断点下无横向溢出，入口保持可点击与键盘焦点可见。
